# derbycatch
Данные: база данных ФАО по мировому рыболовству и аквакультуре 

Определения и ограничения: В файле catch_ddl.sql ddl-структура базы данных apache derby embedded (последняя версия derby 10.17.1.0 совместимость Java 21+) с описанием контента в комментариях. В папке /CSV лежат .csv дампы таблиц этой базы данных, включая основную таблицу данных TSD_GLOBAL_PRODUCTION_QUANTITY (включает вылов (тонн) и аквакультуру (тонн), остальные таблицы либо описательные списки REF_ либо реляционные REL_. Значит типы основных данных, если не указано иное, подразумеваются "тонн". Поля, не описанные комментариями в DDL - не имеют никакого значения и игнорируются (за исключением одинаковых полей описанных один раз за все аналоги). В базе много полей с именованиями на языке отличном от английского - они игноруются, используются только поля _EN (английский язык). SQL-запросы создаются в диалекте Apache Derby (обязательно), диалект Derby является крайне ограниченным по сравнению с современным SQL и при этом обязателен для доступа к базам derby, поэтому надо учитывать тонкости и ограничения диалекта.
Важно, если содержимое поля NAME_EN в списке REF_SPECIES пустое "" -> оно заменяется на содержимое соответствующее (из этой же записи) поля SCIENTIFIC_NAME в прямых скобках [], например "[Chionodraco hamatus]".
Вывод делается без дополений в данные базы данных, as is, имена стран такие как в базе, виды как в базе, без изменений и дополнений, если не указано обратное.
В основной таблице данных TSD_GLOBAL_PRODUCTION_QUANTITY разделение типов данных осуществляется через поле PRODUCTION_SOURCE_DET, в котором три значения "FRESHWATER", "BRACKISHWATER" и "MARINE" означают аквакультуру  (в случае  подсчета суммарного объема аквакультуры, данные с этими тремя видами аквакультуры суммируются), а одно значение "CAPTURE" означает данные по рыболовству.
Не надо создавать дополнительные алгоритмы загрузки драйверов из интернета в программах, только обработка файлов согласно плану задания.
Нумерация колонок на стадии SQL-запросов и python-обработки только для понимания логики, никакая нумерация при оформлении не нужна.
Если не указано обратное (например таблица 3 только по жемчугу и водорослям), данные для формирования таблиц должны исключать группировки видов REF_ISSCAAP_GROUP с таким CODE = 61, 62, 63, 64, (61-64 морзверь) 73 (крокодилы), 81, 82, 83 (81-83 прочие продукты), 91, 92, 93, 94, 95 (91-95 водоросли). Т.е. берутся все за исключением этих перечисленных. Только в таблицах прямо высчитывающих данные по водорослям например берутся группы водорослей 91, 92, 93, 94 и это будет прямо указано в описании.
